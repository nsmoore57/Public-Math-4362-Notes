    Section Programming Basics for Numerical Work

    Lists, decisions, loops, and functions are the small vocabulary from which numerical algorithms are built.

    Lists: ordered, mutable data.

    For trials = [1.0, 1.2, 1.4, 1.5] , indexing starts at zero: trials[0] is the first item and trials[-1] the last. A slice such as trials[1:4] includes positions 1 through 3. Use trials.append(1.6) to add one item. Lists are convenient for collecting an iteration history; NumPy arrays are better for vectorized arithmetic.
    🔗
    🔗

    Range quick reference.

    The stop value is excluded. This makes range(max_iterations) natural for iteration limits.
    🔗
    🔗

    Conditionals and loop control.

    Loops matter because numerical methods repeat the same update over trials or iterations; they turn a one-off calculation into a reproducible algorithm. Conditionals encode decisions such as skipping unusable data, stopping at a tolerance, or choosing an interval from a sign.
    🔗
    for x in [1.0, 1.4, 1.414, 1.42]:
    if x == 1.414:       # skip a deliberately rounded trial
        continue
    value = x**2 - 2
    if value > 0:
        print(f"first positive trial: {x}")
        break
    continue skips the remainder of the current iteration; break exits the loop. Use each only when it clarifies the stopping logic.
    🔗
    🔗

    Algorithmic conditionals.

    value = 1.4**2 - 2
if value < 0:
    description = "below the positive root"
else:
    description = "at or above the positive root"
    This interpretation is specific to \(f(x)=x^2-2\) on \(x\geq 0\text{.}\) More generally, a conditional selects an algorithm’s next action from mathematical evidence.
    🔗
    🔗

    Stopping logic.

    first_positive = None
for x in [1.0, 1.2, 1.4, 1.5, 1.6]:
    if x**2 - 2 > 0:
        first_positive = x
        break
    A stopping condition makes the procedure finite and auditable: the loop exits as soon as its stated goal is met.
    🔗
    🔗

    Ordinary and lambda functions.

    An ordinary function is preferred for an algorithm with a name, documentation, or several steps. A lambda function is a compact anonymous function often passed to a numerical routine.
    🔗
    def f(x):
    """Return x squared minus 2."""
    return x**2 - 2
same_formula = lambda x: x**2 - 2
print(f(1.4), same_formula(1.4))
    Keep lambdas short and readable; do not hide an entire algorithm inside one.

    Debugging: syntax, state, and mathematical plausibility.

    Read the traceback from the final line upward, inspect the named cell, and change one thing at a time. SyntaxError , NameError , TypeError , and IndexError describe different failures. Numerical functions can also raise ValueError when an input lies outside the real-valued domain:
    🔗
    import math
math.sqrt(-1.0)  # ValueError: math domain error
    That error is useful evidence: inspect the input and the mathematical model rather than suppressing it. Code can also run without error and still be mathematically wrong, so compare signs, scales, and known special cases.
    🔗
    🔗

    Deliberate scope.

    Week 1 does not emphasize classes, object-oriented programming, Pandas, or exception architecture. The goal is enough transparent Python to study numerical algorithms.
